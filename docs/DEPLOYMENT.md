# Размещение за существующим nginx

TLS и reverse proxy обслуживает nginx пользователя на сервере. Проект предоставляет только HTTP-приложение
на **127.0.0.1:3000** (HOST=127.0.0.1, PORT=3000). Настроенный upstream nginx должен указывать на этот адрес.
Конфигурация nginx в проект не включается; конфигурационные файлы сервера не изменяются.
Приложению не нужны ключи TLS. Для контейнера внутренний HOST=0.0.0.0, PORT=3000, а Compose публикует
порт только на 127.0.0.1:${PORT:-3000}.

## Новый запуск без контейнера приложения

1. Установите зависимости командой `npm ci` в Node.js 22.12+ либо 24. В `.env` заполните профиль Moodle, `API_TOKEN` и `DATABASE_URL` с реквизитами готовой БД.
2. Выполните `npm run prisma:validate` и `npm run prisma:generate`.
3. Для пустой учебной БД выполните `npm run db:migrate`. Пользователю нужны права на создание схемы `todo` и объектов миграции. Для готовой `todo.tasks` приложению достаточно `USAGE` на схему и `SELECT`, `INSERT`, `UPDATE`, `DELETE` на таблицу. Если выдана только личная схема с другим именем, согласуйте подготовку `todo` с владельцем базы.
4. После миграции можно выполнить `npm run db:status` и `npm run db:check`. Для миграций используйте прямое подключение или пул в режиме сессии.
5. Запустите `npm start` под используемым менеджером процессов. Для облачного PostgreSQL используйте TLS с проверкой сертификата.

## Docker Compose

После подготовки схемы выполните `docker compose up -d --build app`. Compose запускает приложение и передаёт ему `DATABASE_URL` из `.env`. Укажите адрес БД, доступный из контейнера.

## Переход с предыдущей версии с сохранением дел

Схема и физические имена столбцов сохранены. Если БД уже содержит таблицу предыдущего проекта, но ещё
не содержит историю Prisma Migrate, migrate deploy сообщит о непустой БД. Не сбрасывайте базу.
Сначала сделайте резервную копию и сравните таблицу с prisma/migrations/20261123000000_init/migration.sql.
Этот файл соответствует прежней исходной схеме; baseline допустим только при точном соответствии.

```bash
npm ci
npm run prisma:generate
# Только для уже существующей исходной схемы без истории Prisma:
npm run db:baseline
npm run db:migrate
npm run db:status
npm run db:check
```

Baseline отмечает начальную миграцию применённой, не выполняя её SQL и не удаляя данные.
Если схема изменена, сначала подготовьте согласованную миграцию; не отмечайте несовпадающую схему применённой.
Для новой пустой БД baseline не нужен. SQL CHECK-ограничения находятся в миграции, Prisma schema их не описывает.

## Сдача

Проверьте внешний HTTPS через настроенный nginx. После входа убедитесь в совпадении профиля Moodle и
нажмите «Добавить итоговую работу». Выполните независимый SQL CRUD из REVIEWER.md через ту же БД.
Доступы передайте лично преподавателю в Moodle; основные пароли Moodle/ИСУ/Helios не передавайте.
Приложение должно быть доступно весь период проверки. Ничего не публикуется и не отправляется автоматически.

Тема форума: `<Логин Moodle> - <ФИО>`.
В первом сообщении укажите HTTPS-адрес, логин и ФИО, PostgreSQL и площадку, ZIP либо точный commit,
README. Приложите package.json, package-lock.json, .env.example, prisma/schema.prisma и prisma/migrations/.
Фразу «Доступы отправлены лично в Moodle» добавляйте только после фактической отправки.
