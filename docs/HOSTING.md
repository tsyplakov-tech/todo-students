# Анализ площадок — 23.11.2026

Сравнение трёх площадок приведено в README. В `docs/hosting-checks.json` сохранены результаты
первоначальных HTTP-запросов и чтения SSH-баннера, а также результаты последующей проверки Helios.
Облачные аккаунты не предоставлялись и не создавались.

Timeweb Cloud — отечественный платный вариант PostgreSQL. [Документация создания](https://timeweb.cloud/docs/dbaas/dbaas-create)
указывает 8 ГБ для минимальной конфигурации и ограничение одной БД/одного пользователя.
Поэтому именно этот минимум не выбран: отдельный проверяющий требует другого тарифа или согласования.
[Подключение](https://timeweb.cloud/docs/dbaas/postgresql/connect-to-database) возможно по публичному/приватному IP
или домену с TLS. Конкретная цена и число соединений выбираемого тарифа должны быть подтверждены в панели
до покупки; платные ресурсы здесь не заказывались. Временные бонусы не считаются постоянным бесплатным тарифом.

Supabase — предварительная внешняя площадка, поскольку [Free](https://supabase.com/pricing) даёт
500 МБ PostgreSQL и два активных проекта без оплаты. Неактивный проект может быть приостановлен через неделю,
что нужно учитывать на период проверки. [Руководство подключения](https://supabase.com/docs/guides/database/connecting-to-postgres)
различает прямой доступ и pooler; IPv4-подключение выбирается через доступный shared pooler.
Лимит подключений проверяется для выделенного compute; пул приложения ограничен пятью соединениями.
Создание пользовательской роли и вход преподавателя нужно проверить на собственном проекте.

Helios предоставляет учебный доступ без оплаты. Официальные материалы описывают PostgreSQL,
сервер `pg`, БД `studs` и личные схемы студентов. [Курс БД](https://se.ifmo.ru/courses/db),
[курс программирования](https://se.ifmo.ru/courses/programming).

Автор проекта проверил вход по SSH на `helios.cs.ifmo.ru:2222` и подключение к PostgreSQL через SSH-туннель.
Приложение на Helios не размещалось. Квота 1 ГиБ относится только к домашнему каталогу.
Лимит БД определить не удалось. Значение `max_connections=512` относится ко всему серверу PostgreSQL.
Создание отдельной роли или базы данных требует участия администратора, поэтому доступ проверяющему
нужно согласовать.

Первоначальные проверки выполнялись на локальном PostgreSQL 17 в Docker. Текущая конфигурация
приложения подключается к готовой БД через `DATABASE_URL`.
