# Список дел — Express, Prisma и PostgreSQL

Приложение выполняет задание «Список дел: Express и база данных» от 24.10.2026. Используются Node.js 22.12+ или 24, Express 5, Prisma ORM 7.10.1 и PostgreSQL 17. Обычный HTML, CSS и JavaScript обеспечивают вход по токену, просмотр автора, добавление, переименование, завершение и удаление дел. Исходный HTTP-контракт сохранён полностью; дополнительный фреймворк интерфейса не требуется.

Сервер самостоятельно назначает UUID, логин владельца, время создания и начальное состояние. ФИО и логин загружаются из окружения; тело запроса не может их подменить. Токен вводится пользователем и остаётся только в памяти вкладки. Перезагрузка требует повторного входа. Неверная авторизация возвращает 401, ошибки ввода — 400, отсутствие дела — 404, недоступность базы — 503. Ответы с телом содержат JSON, кроме публичного текстового маршрута логина.

Вся работа приложения с делами выполняется через Prisma Client: создание, чтение, обновление и удаление. Репозиторий не содержит SQL-запросов. Схема Prisma сопоставляет поля модели Task со столбцами todo.tasks через map. Миграция дополнительно сохраняет ограничения PostgreSQL для названия и группы. Прямой SQL используется для миграций и независимой проверки преподавателя.

Генератор Prisma создаёт TypeScript-клиент; отдельная команда компилирует его в JavaScript. Само приложение остаётся обычным JavaScript. Сгенерированные файлы не редактируются и воспроизводятся из схемы. Команда build включает генерацию, компиляцию клиента и подготовку каталога dist. Версии Prisma CLI, клиента и адаптера согласованы и зафиксированы вместе с зависимостями в lock-файле.

Приложение и Prisma CLI читают `DATABASE_URL` из `.env`. Для первого запуска пользователь готовой БД может применить миграцию, если ему разрешено создать схему `todo` и объекты миграции. Для запуска с уже подготовленной таблицей достаточно доступа к схеме `todo` и прав CRUD на `todo.tasks`. Отдельный доступ преподавателю согласуется с владельцем базы. Порядок подключения существующей таблицы к истории миграций описан в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

Приложение подключается к готовой PostgreSQL. Для внешнего размещения предварительно выбран Supabase Free; фактический выбор требует собственного аккаунта и проверки ограниченной роли. На Helios проверены SSH и подключение к PostgreSQL через туннель. Приложение на Helios не размещалось.

Заполните профиль Moodle в примере окружения, сгенерируйте случайные пароли и токен, затем выполните команды запуска. После входа нажмите «Добавить итоговую работу»: требуемое персональное дело будет создано через приложение в группе manual. Независимые изменения SQL становятся видны после обновления списка. Существующий nginx сервера обслуживает HTTPS и обращается к приложению по адресу 127.0.0.1:3000; конфигурация nginx в проект не включается и не изменяется.

GitHub Actions проверяет схему, генерацию клиента, линтер и HTTP-контракт на Node.js 24. Тесты миграций, операций с PostgreSQL и браузерный сценарий запускаются вручную с отдельной тестовой БД. Данные Moodle, действующие доступы и внешний адрес нужно заполнить перед сдачей; секреты в архив не входят.

## Установка и запуск

```bash
cp .env.example .env
# Заполните Moodle, API_TOKEN и DATABASE_URL готовой базы.
npm ci
npm run prisma:validate
npm run prisma:generate
npm run db:migrate  # для первичной подготовки схемы с нужными правами
npm start
# Приложение для nginx: http://127.0.0.1:3000
```

```bash
# После подготовки схемы можно запустить приложение в контейнере.
docker compose up -d --build app
# Только проверки/сборка:
npm run check
npm test
npm run build
# dist/ уже содержит JS-клиент; внутри dist: npm ci --omit=dev --ignore-scripts; npm start
```

## Физическая схема и API

| Поле API | Столбец todo.tasks | Тип |
| --- | --- | --- |
| id | id | uuid, PK |
| ownerLogin | owner_login | text, NOT NULL |
| title | title | text, 1–200 символов |
| done | done | boolean, DEFAULT false |
| runId | run_id | varchar(64), ASCII-шаблон |
| createdAt | created_at | timestamptz → ISO 8601 UTC |

| Метод и путь (конечный `/` обязателен) | Ввод | Успех |
| --- | --- | --- |
| GET /login/ | Без токена | 200 text/plain: логин |
| GET /api/author/ | Bearer | 200: login, fullName |
| POST /api/tasks/ | title, runId | 201: дело |
| GET /api/tasks/?runId=manual | Обязательный runId | 200: массив |
| GET /api/tasks/:id/ | UUID | 200: дело |
| PATCH /api/tasks/:id/ | title и/или done | 200: дело |
| DELETE /api/tasks/:id/ | UUID | 204 без тела |

Точная валидация и примеры: [API](docs/API.md). Размещение за nginx и сдача: [DEPLOYMENT](docs/DEPLOYMENT.md). Результаты локальных проверок: [VERIFICATION](docs/VERIFICATION.md).
